## Alteracoes realizadas

- Adicionado passo de testes da API ao workflow de CI.
- Adicionada validacao de `DEPLOY_PATH` antes do deploy por SSH.
- Removido `script_stop`, que nao e suportado por `appleboy/ssh-action@v1.2.2`.
- Adicionada validacao local dos parametros de deploy antes de chamar a action SSH.
- Definidos valores padrao nao sensiveis para `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PORT` e `DEPLOY_PATH`.
- Removida dependencia de `WEB_PORT` no health check do deploy.
- Alterado health check para executar dentro do container `web`.
- Removida execucao duplicada de `prisma migrate deploy` no workflow, porque a API ja executa migracoes no arranque.
- Removida a publicacao da porta `5432` do PostgreSQL desta stack; a base de dados fica interna ao Docker Compose.
- Criado `.env` remoto em `/root/projects/tennis-management-saas/.env` com base no ambiente antigo.
- Ajustado `.env` remoto para `WEB_PORT=8081` e hosts iniciais do SaaS em `tenis.clubtenispro.com`.

## Desvios ao plano

O servidor ja tinha o projeto antigo `tenis-management` em execucao e a ocupar a porta `8080`. Por isso, o novo `.env` foi criado com `WEB_PORT=8081` para evitar conflito imediato.

Durante a revisao, foi clarificado que o PostgreSQL deve ficar interno ao container. O `docker-compose.yml` foi ajustado para remover a publicacao `5432:5432`.

A primeira execucao do GitHub Actions falhou porque `DEPLOY_HOST` nao estava configurado no repositorio novo e porque `script_stop` nao e um input valido da versao usada do `appleboy/ssh-action`. O workflow foi ajustado para usar defaults operacionais nao sensiveis e falhar antes com mensagem clara se faltar a chave SSH.

## Pendencias

- O `docker-compose.yml` ainda tem hosts fixos que devem ser tratados na Fase 1 SaaS.
- O deploy automatico depende de `DEPLOY_SSH_KEY` estar configurado nos secrets do novo repositorio.
